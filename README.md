# KaraLoki v1.2 — очередь караоке и панель ведущего

KaraLoki — небольшое веб-приложение для очереди песен. Сайт размещается на GitHub Pages, данные хранятся в Google Sheets, серверная логика работает через Google Apps Script.

## Что изменилось в v1.2

- Русский язык интерфейса на публичной странице и в панели ведущего.
- Отдельные поля «Название песни» и «Исполнитель»; исполнитель необязателен.
- Публичный вход по единому четырёхзначному коду комнаты.
- Код комнаты меняется ежедневно в 18:00 по московскому времени; код показывается в панели ведущего.
- Имя заказчика запоминается в браузере и закрепляется за устройством после первого успешного заказа.
- После успешного заказа для гостевого устройства действует 15-минутная пауза; таймер показывается под кнопкой заказа.
- Ведущий может заказывать песни от имени RadioLoki.
- Панель ведущего: пауза/продолжение, «Пропустить», немедленный запуск песни из очереди или истории, изменение порядка, удаление, очистка ожидающей очереди.
- История Google Sheets не очищается при очистке очереди.
- Сохранён общий пятиминутный слот воспроизведения и таймер.

## Важные ограничения

`RadioLoki` — это общий идентификатор для удобного доступа, а не безопасная аутентификация. Любой, кто знает это имя и публичный адрес Apps Script, потенциально может вызвать административные действия. Не используйте эту схему для конфиденциальных или публично чувствительных систем.

Код комнаты — защита от случайного доступа гостей, а не полноценная система безопасности. Google Sheet должен оставаться закрытым; гостям не нужно давать доступ к таблице.

Очередь обновляется опросом сервера, а не мгновенной push-трансляцией. Автоматическое переключение происходит при следующем запросе состояния после истечения пятиминутного слота. Если обе страницы закрыты, переключение может произойти при следующем открытии сайта.

## Обновление с v1.1: сначала сохраните данные

Если вы уже настроили Google Sheets для v1.1, **не создавайте новую таблицу и не удаляйте существующие вкладки**. v1.2 использует те же вкладки `Queue`, `Playback`, `History` и существующее свойство `SPREADSHEET_ID`.

Перед обновлением рекомендуется сделать копию таблицы: Google Sheets → Файл → Создать копию.

### 1. Обновить Apps Script

1. Откройте существующую Google-таблицу KaraLoki.
2. Выберите **Расширения → Apps Script**.
3. Откройте `Code.gs`.
4. Скопируйте весь текст из `google-apps-script/Code.gs` в архиве v1.2 и замените им старый код целиком.
5. Нажмите **Сохранить**.
6. Убедитесь, что в **Настройки проекта → Свойства скрипта** сохранено свойство `SPREADSHEET_ID` с ID вашей прежней таблицы. Не меняйте и не удаляйте его.
7. Запустите функцию `setupKaraLoki` из выпадающего списка функций и подтвердите разрешения Google, если появится запрос. Она создаёт только отсутствующие вкладки и не очищает имеющиеся данные.

### 2. Опубликовать новую версию Apps Script

1. В редакторе Apps Script откройте **Развернуть → Управление развертываниями**.
2. Выберите существующее развертывание типа **Веб-приложение** и нажмите значок редактирования.
3. В поле версии выберите **Новая версия**.
4. Проверьте настройки: **Выполнять от имени: Я**, **У кого есть доступ: Все** (иначе гости не смогут отправлять запросы).
5. Нажмите **Развернуть**.
6. Скопируйте URL веб-приложения, заканчивающийся на `/exec`. Если URL не изменился, прежний адрес остаётся пригоден.

> Если вы создаёте новое развертывание вместо редактирования старого, обязательно обновите URL в `js/config.js` на следующем шаге.

### 3. Настроить сайт

1. Откройте файл `js/config.js`.
2. Вставьте URL веб-приложения между кавычками вместо `PASTE_YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_URL_HERE`.
3. Сохраните файл.

### 4. Обновить GitHub Pages

1. Распакуйте архив `KaraLoki_v1.2.zip`.
2. Откройте папку `KaraLoki`.
3. Загрузите **содержимое этой папки** в корень существующего GitHub-репозитория, заменив старые файлы. Не загружайте ZIP как единственный файл и не создавайте вложенную папку `KaraLoki/KaraLoki`.
4. Убедитесь, что на верхнем уровне репозитория лежат `index.html`, `admin.html`, `README.md`, `.nojekyll`, а также папки `css`, `js`, `google-apps-script`.
5. Зафиксируйте изменения (Commit changes / Push).
6. В GitHub откройте **Settings → Pages**. Источник должен быть **Deploy from a branch**, ветка `main`, папка `/(root)`.
7. Дождитесь публикации. Публичная страница обычно доступна по адресу `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`, панель — `admin.html` в конце этого адреса.

Если GitHub Pages уже работал для v1.1, повторно включать его обычно не требуется — достаточно заменить файлы и отправить commit.

## Первичная настройка с нуля

Если у вас ещё нет таблицы и Apps Script:

1. Создайте Google-таблицу.
2. Скопируйте ID из URL — значение между `/d/` и `/edit`.
3. Откройте **Расширения → Apps Script**.
4. Замените содержимое `Code.gs` кодом из `google-apps-script/Code.gs`.
5. В настройках проекта добавьте Script Property `SPREADSHEET_ID` со значением ID таблицы.
6. Сохраните и запустите `setupKaraLoki`.
7. Разверните как веб-приложение (выполнять от имени вас, доступ — все).
8. Вставьте URL `/exec` в `js/config.js`.
9. Загрузите проект в GitHub и включите GitHub Pages.

## Проверка после обновления

- Откройте публичную страницу: без кода комнаты очередь и форма заказа скрыты.
- Введите актуальный четырёхзначный код, показанный в панели ведущего.
- Проверьте, что имя гостя сохраняется после перезагрузки страницы.
- Закажите песню без исполнителя и с исполнителем.
- После заказа проверьте 15-минутный таймер и запрет повторного заказа с того же браузера.
- Откройте `admin.html`, войдите в панель и проверьте отображение кода комнаты.
- Добавьте песню от ведущего; она должна появиться в очереди как заказ `RadioLoki`.
- Проверьте паузу, продолжение и «Пропустить».
- Запустите песню кнопкой ▶ из очереди, затем из истории.
- Проверьте перемещение песен вверх/вниз и удаление одной песни.
- Очистите очередь и убедитесь, что строки на вкладке `History` не удалены.
- Проверьте пятиминутный таймер.

## Примечания по хранению данных

- `Queue` хранит запросы и их статусы. Очистка очереди меняет статус ожидающих строк на `Cleared`, не удаляя их.
- `Playback` хранит текущую песню и состояние таймера.
- `History` хранит записи исполненных, пропущенных, прерванных и удалённых песен. Кнопка «Очистить очередь» эту вкладку не трогает.
- ID устройства хранится в localStorage браузера. Очистка данных сайта или другой браузер создаст новый ID; это ограничение для вечеринки, а не проверка личности.
- Гостевой код комнаты и имя гостя хранятся в localStorage; имя также закрепляется на сервере за ID устройства. Смена имени с того же устройства не допускается. Для нового ID потребуется другой браузер/профиль или очистка данных сайта (при этом будет создан новый ID).
- Пятиминутный таймер — слот очереди, он не определяет фактическое воспроизведение музыки.

# KaraLoki v1.4 — очередь караоке и панель ведущего

KaraLoki — веб-приложение для караоке-очереди. Сайт размещается на GitHub Pages, данные хранятся в Google Sheets, серверная логика работает через Google Apps Script.

## Что нового в v1.4

- Удалён код комнаты: гостю больше не нужен ежедневный четырёхзначный код.
- Удалена генерация и проверка DeviceID. Новая версия не читает и не создаёт идентификатор устройства.
- Гость вводит имя. Новое имя появляется в списке ожидающих пользователей и требует подтверждения ведущего.
- Ранее подтверждённое имя автоматически принимается при повторном входе; повторное подтверждение не требуется.
- Подтверждённое имя нельзя изменить в текущей сессии. Кнопка «Выйти» внизу формы позволяет завершить сессию и войти под другим именем.
- После отклонения заявки запись ожидающего пользователя удаляется, поэтому гость может отправить другое имя.
- В панели ведущего появились вкладки **Queue** и **Users**.
- Вкладка Users показывает ожидающие и подтверждённые имена. Действия: подтвердить, отклонить, снять cooldown, временно заблокировать заказы на 30 минут.
- Cooldown 15 минут хранится в Google Sheets по нормализованному имени, а не по браузеру или DeviceID.
- Удаление песни из очереди снимает cooldown её заказчика. Очистка очереди снимает cooldown у всех затронутых заказчиков.
- История поддерживает Play, Hide и Delete.
- Фоновое обновление — каждые 10 секунд. После успешных действий интерфейс запрашивает новое состояние сразу. Локальные таймеры обновляются каждую секунду.
- Пятиминутный слот воспроизведения, пауза, продолжение, пропуск, перестановка очереди и заказ песни от RadioLoki сохранены.
- Версия v1.4 указана в README, интерфейсе и Apps Script `Code.gs`.

## Важные ограничения выбранной системы имён

Имя — это идентификатор гостя, а не подтверждение личности. Любой человек, который знает уже подтверждённое имя, может ввести его и получить доступ под этим именем. Все люди, использующие одно и то же имя, будут совместно использовать его cooldown и временную блокировку. Без PIN, пароля, DeviceID или внешней проверки личности невозможно отличить двух людей с одинаковым именем или запретить одному человеку создать другое имя после выхода.

`RadioLoki` зарезервировано для ведущего и не принимается как гостевое имя. Административный доступ по-прежнему является общей проверкой имени `RadioLoki`, а не безопасной аутентификацией. Не используйте эту схему для конфиденциальных данных.

Временная блокировка на 30 минут запрещает заказы, но публичная очередь остаётся доступна для просмотра. После окончания блокировки доступ к заказам восстанавливается автоматически.

## Обновление с v1.3: сначала сохраните данные

1. Сделайте копию Google Sheets: **Файл → Создать копию**.
2. Скачайте и распакуйте `KaraLoki_v1.4.zip`.
3. В существующей Google-таблице откройте **Расширения → Apps Script**.
4. Полностью замените содержимое `Code.gs` файлом `google-apps-script/Code.gs` из v1.4 и сохраните.
5. Проверьте, что Script Property `SPREADSHEET_ID` по-прежнему содержит ID вашей существующей таблицы. Не удаляйте его.
6. В редакторе Apps Script выберите функцию `setupKaraLoki` и нажмите **Выполнить**. При первом запуске подтвердите разрешения.
   - Будет создан новый лист `Users`.
   - В существующий лист `History` будут добавлены столбцы `hidden` и `entryId`, если их ещё нет. Старым записям будут присвоены уникальные `entryId`, чтобы Hide/Delete работали с конкретной строкой истории.
   - Существующие строки Queue, Playback и History не очищаются.
   - Старые столбцы `deviceId` автоматически удаляются из Queue и History при запуске `setupKaraLoki`; остальные строки и поля сохраняются.
7. Откройте **Развернуть → Управление развертываниями**, отредактируйте существующее веб-приложение, выберите **Новая версия** и нажмите **Развернуть**. Сохраните URL `/exec`.
8. В `js/config.js` проекта GitHub Pages вставьте этот URL в `API_URL`. Значение `REFRESH_MS` по умолчанию — `10000`.
9. Замените файлы в корне GitHub-репозитория содержимым папки проекта v1.4. Не загружайте ZIP как единственный файл и не создавайте вложенную папку `KaraLoki/KaraLoki`.
10. Сделайте Commit / Push и дождитесь обновления GitHub Pages.

### Что будет с гостями и cooldown после обновления

- В v1.3 не было списка подтверждённых имён, поэтому v1.4 не может достоверно определить, какие старые имена были бы подтверждены. Лист `Users` создаётся пустым. При первом входе каждый гость отправит имя на подтверждение; после этого повторный вход под тем же именем будет автоматическим.
- Старые cooldown, хранившиеся в Script Properties по DeviceID, не переносятся. После перехода cooldown начинает учитываться по имени при первом новом заказе.
- Старые записи очереди и истории остаются в таблице. Столбцы `deviceId` удаляются миграцией; новая схема больше не содержит идентификаторов устройств.

## Структура Google Sheets

- `Queue` — активные и прошлые записи очереди, статусы и позиции. DeviceID в этой версии отсутствует.
- `Playback` — текущая песня, пауза и таймер.
- `History` — история исполнения. `hidden` управляет видимостью записи, а уникальный `entryId` позволяет скрывать и удалять конкретную запись, даже если одна песня запускалась несколько раз. DeviceID в этой версии отсутствует.
- `Users` — имя, нормализованный ключ имени, статус (`Pending` / `Confirmed`), время окончания cooldown и временной блокировки.

Не переименовывайте столбцы или листы вручную.

## Первичная настройка с нуля

1. Создайте Google-таблицу.
2. Скопируйте ID из URL — значение между `/d/` и `/edit`.
3. Откройте **Расширения → Apps Script** и замените `Code.gs` содержимым `google-apps-script/Code.gs`.
4. В **Настройки проекта → Свойства скрипта** добавьте `SPREADSHEET_ID` со значением ID таблицы.
5. Сохраните и запустите `setupKaraLoki`.
6. Разверните как веб-приложение: **Выполнять от имени: Я**, **У кого есть доступ: Все**.
7. Скопируйте URL веб-приложения `/exec` в `js/config.js` в поле `API_URL`.
8. Загрузите проект в GitHub и включите GitHub Pages.

## Проверка v1.4 после развертывания

1. Откройте публичную страницу и введите новое имя. Оно должно появиться во вкладке Users → ожидающие.
2. Подтвердите имя в панели. Гостевая страница должна открыть форму заказа без повторного ввода имени.
3. Выйдите и войдите под тем же именем: оно должно приниматься автоматически.
4. Попробуйте заказать песню. В Users должен появиться cooldown, а на публичной странице — обратный отсчёт.
5. Выйдите, очистите данные сайта и снова введите то же имя. Сервер должен вернуть прежний cooldown.
6. Удалите песню этого гостя из очереди. Его cooldown должен сняться.
7. Закажите несколько песен разными подтверждёнными именами и очистите очередь. Cooldown затронутых гостей должен сняться.
8. Примените 🔨 к подтверждённому пользователю. Его заказы должны быть заблокированы на 30 минут, но очередь остаётся видимой.
9. Проверьте подтверждение и отклонение новых имён.
10. Проверьте Queue: пауза, продолжение, пропуск, перемещение, Play из истории, Hide и Delete.
11. Проверьте, что фоновое обновление происходит примерно раз в 10 секунд, а после действий интерфейс обновляется сразу.

## Примечания

- Пятиминутный таймер — слот очереди, а не фактическое определение длительности музыкального файла.
- Автоматический переход к следующей песне происходит при следующем запросе состояния после истечения слота.
- Если все страницы закрыты, переход может произойти при следующем открытии сайта.
- Apps Script и Google Sheets должны быть доступны гостям через веб-приложение; саму таблицу не нужно открывать для гостей.
